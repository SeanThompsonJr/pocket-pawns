What is this?

This page is only the part you see, called the frontend. It looks like a live game room, but the opponent, the lobby and your rating are all made up inside this page. Nobody is on the other side.

Turn on Show requests to see what each button would ask a real server (the backend), and how it would answer, one step at a time. It's part of a series about the backend. This one covers how a page and a server talk, known as REST API design.

    How this section talks to the server

    An endpoint is an address on the server that the page can ask for something. This whole section uses just one: /players/me. "me" means whoever is signed in, so the same address works for every player.

    • GET When the page opens, it asks for your profile: name, rating, record and recent games.
    • PATCH When you press Save settings, it sends only what you changed.

    Pocket Pawns is a design concept

    It's only the part you see, with nothing behind it. The opponent's moves, the lobby and your rating are written into this page, which is why they never change. A real game room needs a server that both players' phones can talk to.

    Every name, rating and game here is a sample. No data leaves this page.

    Every button here is a request

    This game room is only the part you see, called the frontend. Here's how to peek at what it would ask a real server, the backend.

    1. Turn on Show requests at the top of the page.
      Show requests
    2. Press a button with a blue tag, like Next move. The tag shows what kind of request it is.
      POSTNext move
    3. Follow the trip, one step at a time. The card flips over and walks you from your browser to the server and back.
      BrowserServerDatabase

    On a wide screen, press Show on left to keep the walkthrough beside the board instead.
